name: Security Intelligence mobile boundary
description: Visual and product constraints for the Security Intelligence mobile redesign.
---

Security Intelligence uses a black/dark evidence-workspace treatment across Overview, CVE Table, Compare, and expanded CVE/AI states. Redesign work must accommodate the current feature set exactly rather than introducing new security workflows or conclusions.

**Why:** The user explicitly wants the existing implementation and capabilities preserved, with visual/mobile improvements only, and confirmed the existing black first screen should define the entire feature.

**How to apply:** Preserve the three existing tabs, vendor selection rules, CVE filters and pagination, NVD links, expandable evidence, AI explanation states/disclaimer, confirmed-CPE semantics, compare limits and states. Do not add alerts, remediation, risk scores, asset exposure, saved views, new data sources, or other unsupported actions.
