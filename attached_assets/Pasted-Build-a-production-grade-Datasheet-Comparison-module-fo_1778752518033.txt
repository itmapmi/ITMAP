Build a production-grade Datasheet Comparison module for Spectio.ai, an AI-native 
IT market research platform. This module is one component of a larger platform that 
already has: vendor evaluation, product evaluation, ecosystem evaluation, custom 
market builder, AI-based scoring, forecast builder, and RFP generator.

═══════════════════════════════════════════════════════════════════
PROJECT OVERVIEW
═══════════════════════════════════════════════════════════════════

Build a web application that allows buyers of enterprise IT hardware (storage 
arrays, servers, networking equipment) to compare product datasheets side-by-side. 
The system automatically discovers, downloads, extracts, and normalizes datasheet 
content from vendor websites on a weekly basis using AI agents.

PRIMARY USERS: Enterprise IT buyers, procurement teams, solution architects 
evaluating hardware purchases.

CORE VALUE PROP: Replace the manual process of downloading 8+ PDFs from vendor 
sites and comparing specs in spreadsheets. Provide normalized, sourced, current 
comparisons with diff highlighting and change alerts.

═══════════════════════════════════════════════════════════════════
TECH STACK
═══════════════════════════════════════════════════════════════════

- Frontend: Next.js 14 (App Router) + TypeScript + Tailwind CSS + shadcn/ui
- Backend: Next.js API routes + tRPC for type-safe APIs
- Database: PostgreSQL via Prisma ORM (use Replit's built-in PostgreSQL)
- Authentication: Clerk or NextAuth (pick simplest to set up on Replit)
- File Storage: Replit Object Storage for PDF files
- Background Jobs: Inngest or a simple cron-based system using Replit's always-on
- LLM Integration: Anthropic Claude API (claude-sonnet-4-5 for extraction, 
  claude-opus-4-5 for validation). Use the ANTHROPIC_API_KEY environment variable.
- PDF Processing: pdf-parse for text, pdf-lib for manipulation, Claude vision 
  for complex layouts
- Web Scraping: Playwright for JS-heavy sites, Cheerio for static HTML
- PDF Viewer: react-pdf for in-app viewing
- Charts: Recharts for any data visualization
- State Management: Zustand for client state, TanStack Query for server state

DATABASE SCHEMA (Prisma)
═══════════════════════════════════════════════════════════════════

Create the following models:

1. Market
   - id, name, slug, category (storage/networking/server/firewall/custom)
   - schemaDefinition (JSON - the spec schema for this market)
   - createdBy, createdAt, updatedAt
   - isPublic (boolean)

2. Vendor
   - id, name, slug, websiteUrl, logoUrl
   - datasheetDiscoveryConfig (JSON - URLs, selectors, patterns)
   - lastScannedAt, scanHealthStatus (healthy/degraded/failed)

3. Product
   - id, vendorId, marketId, name, slug, subcategory
   - productPageUrl, currentDatasheetUrl
   - description, isActive
   - createdAt, updatedAt

4. Datasheet
   - id, productId, fileUrl (Replit Object Storage), fileHash
   - downloadedAt, fileSize, pageCount
   - extractionStatus (pending/processing/completed/failed)
   - extractedData (JSON - normalized specs per market schema)
   - rawText (full PDF text for search)
   - version (incremented on each new version)
   - previousDatasheetId (for diff tracking)

5. ExtractedSpec
   - id, datasheetId, category, attributeName
   - rawValue, normalizedValue, unit
   - sourcePageNumber, sourceQuote
   - confidence (0-1), needsReview (boolean)
   - validationStatus

6. Comparison (saved user comparisons)
   - id, userId, name, marketId
   - pinnedProductIds (array)
   - createdAt, lastViewedAt

7. ChangeAlert
   - id, datasheetId, changeType (new/updated/spec_changed)
   - changedFields (JSON), severity
   - createdAt, notifiedUsers (array)

8. AgentRun
   - id, vendorId, runType (discovery/extraction/validation)
   - startedAt, completedAt, status
   - logsJson, errorMessage

9. User
   - id, email, name, role (admin/analyst/buyer)
   - subscribedMarkets (array), subscribedProducts (array)

═══════════════════════════════════════════════════════════════════
AGENT PIPELINE (CRITICAL - BUILD CAREFULLY)
═══════════════════════════════════════════════════════════════════

Build a multi-stage pipeline that runs weekly via cron. Each stage is a 
separate job that can be retried independently.

STAGE 1 — Discovery Agent (per vendor):
- Load vendor's datasheetDiscoveryConfig
- Use Playwright to visit product pages (handles JS-rendered sites)
- Find datasheet links via:
  * Configured CSS selectors (preferred)
  * Heuristic search for "datasheet", "spec sheet", "product brief", 
    "tech specs" link text or URLs containing these terms
  * Fallback to LLM-based extraction: pass page HTML to Claude and ask 
    "find datasheet PDF links for these products: [list]"
- Output: list of {productId, datasheetUrl} pairs
- Log all discovery attempts to AgentRun

STAGE 2 — Download Agent:
- For each datasheet URL, download the PDF
- Compute SHA-256 hash
- If hash matches existing datasheet for this product → skip, mark "verified current"
- If hash differs or new → upload to Replit Object Storage
- Create new Datasheet record with version = previous + 1
- Extract raw text using pdf-parse

STAGE 3 — Extraction Agent:
- Load market schema for the product's market
- Build extraction prompt:
  * System: "You are extracting structured specs from a product datasheet. 
    Extract ONLY values explicitly stated. Mark anything ambiguous. Include 
    page number and exact quote for each value."
  * User: market schema (attributes to extract) + datasheet text (and 
    images if needed via Claude vision)
- Use Claude Sonnet 4.5 with structured output (JSON schema)
- For complex tables/layouts, render specific PDF pages as images and use 
  Claude's vision capability
- Store extracted values in ExtractedSpec table
- Each spec includes: rawValue, normalizedValue (after unit conversion), 
  sourcePageNumber, sourceQuote, confidence

STAGE 4 — Normalization Agent:
- For each ExtractedSpec, normalize units (TB to GB, Gbps to Mbps, etc.)
- Detect "non-comparable" values: e.g., "up to 2M IOPS" vs "sustained 800K IOPS"
- For attributes flagged as having different measurement conditions, mark 
  needsReview = true and add explanation
- Compute comparative rankings within the market

STAGE 5 — Validation Agent:
- Use Claude Opus 4.5 (more capable) to sanity-check extractions
- Prompt: "Here is an extracted spec for [product class]. Does this value 
  make sense? Flag if it seems wrong by an order of magnitude or contradicts 
  known product class norms."
- Anything flagged → needsReview = true → queue for human review

STAGE 6 — Diff & Alert Agent:
- Compare new Datasheet against previousDatasheet
- For each attribute, detect changes
- Create ChangeAlert records for material changes
- Notify subscribed users via email (use Resend or similar)
