| **MySQL**                                                     | IBM does not document a native MySQL agent in Spectrum Protect for Databases. Spectrum Protect Plus supports MySQL via its generic database-application support (snapshots, cataloging, data reuse) in hybrid/cloud setups. ([IBM Redbooks][1])                                 |
| **MSSQL (SQL Server)**                                        | Spectrum Protect for Databases offers a “Data Protection for Microsoft SQL Server” module, providing full, differential, and transaction-log backups, point-in-time restores, integration with AlwaysOn (with restrictions), and policy-based retention. ([IBM][2])             |
| **Oracle**                                                    | Spectrum Protect’s “Data Protection for Oracle” uses RMAN + SBT-API interface to integrate with IBM Spectrum Protect server. It supports full, incremental, archive log backups, cluster (RAC) awareness (with caveats) and uses the Spectrum Protect policy engine. ([IBM][3]) |
| **MongoDB**                                                   | Spectrum Protect Plus supports MongoDB protection in its database-application portfolio, enabling backup, restore, and data reuse for MongoDB instances (on supported platforms). ([IBM Redbooks][1])                                                                           |
| **IBM DB2**                                                   | Spectrum Protect Plus supports IBM Db2 as one of its target databases, handling backup, restore, and data reuse workflows for Db2 instances on supported hosts. ([IBM][4])                                                                                                      |
| **PostgreSQL**                                                | IBM’s publicly documented support for PostgreSQL under Spectrum Protect is limited. While Spectrum Protect Plus may protect workloads including PostgreSQL via generic support, no dedicated module or deep integration is clearly documented. ([IBM][4])                       |
| **Oracle RAC**                                                | Spectrum Protect’s Oracle module supports RAC clusters (multi-node) via RMAN integration, but with limitations: recovery not server-pool aware and shared snapshot control file required. ([IBM][5])                                                                            |
| **Apache Cassandra**                                          | No explicit IBM documentation indicates native support for Cassandra under Spectrum Protect. Cassandra might be protected via snapshot or export workflows, then stored under generic backup policies.                                                                          |

Backup would rely on exporting DynamoDB tables (e.g. to S3) and then ingesting those into Spectrum Protect policies.                                                                                               |
| **Amazon Redshift**                                           | No published native Redshift module in Spectrum Protect; backup may rely on orchestrating Redshift snapshots or unloads to external storage, then protecting those outputs.                                                                                                     |
| **Amazon ElastiCache**                                        | IBM does not document a module for ElastiCache. Protection likely depends on capturing Redis snapshot files or backups and assigning them to Spectrum Protect backup policies.                                                                                                  |
| **Amazon MemoryDB**                                           | Similar to ElastiCache, no native support is documented. Backup would depend on Redis snapshots exported and then backed up via generic ingestion.                                                                                                                              |
| **Amazon DocumentDB**                                         | IBM documentation does not describe a DocumentDB-specific module. Protection would likely rely on snapshot or dump of the data and ingestion into Spectrum Protect storage.                                                                                                     |
| **Amazon Neptune**                                            | No explicit support is documented for Neptune. Backup would rely on snapshot/export and then storage via IBM Spectrum Protect.                                                                                                                                                  |
| **Amazon Keyspaces (Cassandra)**                              | No public documentation shows Spectrum Protect supporting Keyspaces. Protection must come via export of Cassandra data or integration at file / snapshot level.                                                                                                                 |
| **Amazon Timestream**                                         | IBM does not document Timestream support. Backup would likely require data export (e.g. CSV or Parquet) and subsequent ingestion into Spectrum Protect repository.                                                                                                              |
| **Azure SQL Database**                                        | IBM Spectrum Protect Plus supports protecting databases in Azure. However, direct PaaS agent-based backup for Azure SQL DB is not clearly documented—likely via orchestration of native backups. | **Azure Cosmos DB**                                           | No explicit documentation of Cosmos DB support. Backup would likely depend on export (e.g. change feed or snapshot) and ingestion into Spectrum Protect storage.                                                                                                                |
| **BigQuery**                                                  | No public integration; backup would require exporting BigQuery datasets into files (e.g. GCS) and then protecting with Spectrum Protect.                                                                                                                                        |

Protection would rely on snapshot or data export to external storage and backup via Spectrum Protect.                                                                                                                       |
