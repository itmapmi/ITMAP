B. (Optional but recommended) Pre‑extract sentence‑level evidence
If your commentary notes are long, do this server‑side so the model sees ready‑to‑quote snippets:

function topEvidenceSentences(text: string, maxSentences = 2): string[] {
  // very simple heuristics; replace with your own
  const sents = text
    .replace(/\s+/g, ' ')
    .split(/(?<=[.!?])\s+/)
    .map(s => s.trim())
    .filter(Boolean);
  // rank: prefer sentences containing strength/risk signals
  const score = (s: string) =>
    (/\b(strong|full|native|deep|improv|lag|lack|limited|gap|risk|roadmap)\b/i.test(s) ? 1 : 0) +
    (s.length <= 140 ? 0.5 : 0) +
    (/\bnot\b|\bhowever\b|\bbut\b/i.test(s) ? 0.25 : 0);
  return sents.sort((a,b) => score(b)-score(a)).slice(0, maxSentences);
}


Then either replace commentary with the best sentence, or pass an extra evidence_sentences array—your choice. The prompt works with either; extractive quotes will be taken from what you pass.

6) Quick diagnostic checklist (why answers seemed “inaccurate”)

Commentary not passed or too long → truncated
Fix: Pass the best 1–3 sentences per item (≤ 500 chars total) with source_id.

Model not required to surface commentary
Fix: The v2 prompt forces a snippet and citation for each cell and bullet.

Contradictory data (e.g., high score but risk‑laden commentary)
Fix: The v2 prompt highlights ⚠️ conflicts instead of silently ignoring commentary.

Alias mismatch (e.g., “MSFT” vs “Microsoft”)
Fix: Normalize names server‑side before building DATA_CONTEXT.

Too much irrelevant data (token overflow → model misses commentary)
Fix: Slice to just the market, vendors, and requested features/ISVs/news for the query.
