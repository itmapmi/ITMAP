| Database / Service                                            | Veeam Backup Capabilities (≈ 50 words)                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **MySQL**                                                     | Veeam Agent for Linux supports application-aware processing of MySQL (InnoDB & MyISAM) by flushing and locking tables, performing a consistent snapshot of the volume, then unlocking. ([Veeam Software][1]) It supports both “Require success” and “ignore failures” modes. ([Veeam Software][2]) |
| **MSSQL**                                                     | Veeam has mature support for Microsoft SQL Server, including transaction log backup, point-in-time restore, database-level restore (Veeam Explorer for SQL), and ability to restore individual databases or objects.                                                                               |
| **Oracle**                                                    | Veeam supports consistent backups of Oracle via VSS or via storage snapshots + pre/post scripts; it can handle archived redo logs, and allow point-in-time recovery of Oracle databases in supported configurations.                                                                               |
| **MongoDB**                                                   | Native support is limited; often MongoDB is protected via VM/host snapshot or via storage integration. Veeam doesn’t provide full object-level “Explorer” functionality for MongoDB in many versions.                                                                                              |
| **IBM DB2**                                                   | Veeam supports DB2 mostly via image/volume snapshot and guest processing scripts; advanced DB2-aware backup and item-level restore are less mature or restricted depending on version and platform.                                                                                                |
| **PostgreSQL**                                                | On Linux, Veeam can do application-aware processing for PostgreSQL (flush, freeze, snapshot) similar to MySQL behavior. On Windows, support is more limited.                                                                                                                                       |
| **Oracle RAC**                                                | RAC (clustered Oracle) poses complexity; Veeam can back up at the host/cluster volume snapshot level, but cluster-aware or instance-aware coordinated backup isn’t fully native in many cases.                                                                                                     |
| **Apache Cassandra**                                          | Cassandra is often backed up using host-level snapshots or custom scripts; Veeam does not provide deep native Cassandra “Explorer” features, so you rely on file/volume capture plus custom scripting.                                                                                             |
| **AWS Aurora (MySQL/PostgreSQL)**                             | Veeam Backup for AWS supports automated snapshots for Aurora clusters, cross-region replication, and restores. However, multi-region global Aurora topology must be rebuilt manually after restore. ([Veeam Software][3])                                                                          |
| **Amazon DynamoDB**                                           | Veeam Backup for AWS supports cloud-native backups of DynamoDB tables, restore operations, and cross-region copy of backups. ([Veeam Software][3])                                                                                                                                                 |
| **Amazon Redshift**                                           | Via Veeam Backup for AWS, you can create cloud-native backups of Redshift clusters and restore them. ([Veeam Software][3])                                                                                                                                                                         |
| **Amazon ElastiCache**                                        | Veeam does not have deep, application-aware support for ElastiCache (Redis/Memcached). Typically backups are via snapshot integrations at the service level or host-level backups.                                                                                                                 |
| **Amazon MemoryDB**                                           | Similar to ElastiCache, Veeam relies on snapshot or service-level backup mechanisms; native application-aware features are limited or not documented.                                                                                                                                              |
| **Amazon DocumentDB**                                         | Veeam treats DocumentDB via Veeam Backup for AWS using snapshot-based backups and restores. DocumentDB’s managed snapshots are leveraged rather than deep “Explorer” level integration.                                                                                                            |
| **Amazon Neptune**                                            | Veeam’s support for Neptune is primarily via backup of the underlying managed service snapshot; full graph-aware restores (vertex/edge-level) are not deeply integrated.                                                                                                                           |
| **Amazon Keyspaces (Cassandra)**                              | Keyspaces (AWS Cassandra service) is backed via snapshot exports or service APIs; Veeam may capture via volume snapshot or via AWS backup APIs, but no deep “Explorer” support.                                                                                                                    |
| **Amazon Timestream**                                         | Veeam does not provide native Timestream-level integration; backups would rely on service export APIs or underlying snapshot mechanisms rather than Veeam-native object level support.                                                                                                             |
| **Azure SQL Database**                                        | Azure SQL DB is protected via Azure-native backups; Veeam can orchestrate or coordinate via Azure integration, but does not replace Azure’s internal snapshoting.                                                                                                                                  |
| **Azure Cosmos DB**                                           | Cosmos DB is managed; Veeam may capture through Azure resource snapshot or API automation, but lacks native Cosmos object-level integration in many versions.                                                                                                                                      |
| **BigQuery**                                                  | BigQuery is a serverless analytics database; Veeam does not natively integrate at object level. Backups rely on export (e.g. to GCS) and orchestration external to Veeam.                                                                                                                          |
| **Bigtable**                                                  | For Bigtable, Veeam relies on integration with Google Cloud snapshot or export APIs; deep Veeam-native item-level restores are limited or not supported.                                                                                                                                           |
| **AlloyDB for PostgreSQL**                                    | AlloyDB is a managed PostgreSQL engine; Veeam may integrate via managed snapshot or API export, but fully native Veeam-aware features (point-in-time restore, Explorer) may be limited.                                                                                                            |
| **MongoDB Atlas (on GCP)**                                    | For MongoDB Atlas, backups are handled by the Atlas service; Veeam integration would rely on API/export workflows and snapshot capture rather than deep internal support.                                                                                                                          |
| **Alibaba Cloud RDS (MySQL, SQL Server, PostgreSQL, Oracle)** | Veeam can protect Alibaba RDS instances via snapshot-based approaches where the cloud provider supports it; native database-aware features depend on RDS engine and permission levels.                                                                                                             |
| **Huawei Cloud GaussDB**                                      | Veeam integration is limited; backup is via cloud provider snapshots or export services. Full application-aware, point-level features are not broadly documented.                                                                                                                                  |
| **IBM Db2 on IBM Cloud**                                      | Veeam backs IBM Db2 on IBM Cloud via VM/host-level snapshots and guest scripting; advanced DB2 object-level restore capabilities depend on platform support.                                                                                                                                       |
| **Oracle Cloud Autonomous Database**                          | Autonomous DB is fully managed and does its own backups; Veeam’s role is limited to orchestrating exports or capturing underlying snapshot management via APIs, rather than providing deep internal DB restore capability.                                                                         |
